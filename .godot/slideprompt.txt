Text Formatting:
- # for H1, ## for H2, ### for H3 (optionally #- or ##- or ###- does gray color with those H1/H2/H3, #! ##! ###! red color, #$, ##$, ###$ green color, #@, ##@, ###@ purple color)
- **bold**
- ~~strikethrough~~
- ~^wavy text^~
- ^^ colored text ^^ (always blue)
- [color=#RRGGBB]colored text[/color]

Color Semantic Usage (for H1, H2, H3):
- Red (#!) for warnings, important concepts, or common pitfalls
- Green (#$) for best practices, tips, or successful outcomes
- Purple (#@) for definitions or key terminology
- Blue (#) for code-related concepts or technical terms
- Gray (#-) for additional context or side notes

Image Handling:
- Suggest image placements using "=> LeftImage" or "=> RightImage" with descriptions
- Describe needed diagrams or visual aids in comments like: // Need: Class inheritance diagram
- Recommend places for images that would help explain:
  * Code output examples
  * Visual diagrams
  * UI mockups
  * Flow charts
- Use // [placeholder] comments to indicate where custom screenshots or demos should go (the // in the beginning of the line makes the line be treated as a comment and not be shown in the slide)

Layout Tips:
- Use HBox for horizontal layouts with [alignment=X] where X is 0 (left), 1 (center), 2 (right)
- Use VBox for vertical layouts with custom spacing: [theme_override_constants/separation=20]
- For important code examples, use larger font: => Code [code_font_size=24]
- Use [expand_horizontal=true/false] and [expand_vertical=true/false] for control over element sizing

Interactive Elements:
- Add pauses ( || ||) before revealing key concepts or answers

Text Attributes:
=> Text [font_size = X]
Where X is the desired font size. The default for a good side is about 28~32. A new text is not needed to change font_size, it's possible to change the font size with bbcode within the text itself [font_size=42]Like this[/font_size]. Never start a slide with => Text, there's an implicit one at the start so adding a second explicit one can cause problems. Adding parameters to text is also optional, it has implicit default parameters.

5. Incorporate lists, tables, and code blocks when relevant to the topic.
6. Use slide pauses ("|| ||") strategically to control information flow.
